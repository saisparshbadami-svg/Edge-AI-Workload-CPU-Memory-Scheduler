Project Overview

Edge Device Constraints & OS Orchestration

How modern embedded operating systems balance real-time neural network deadlines against strictly constrained RAM.

Autonomous edge systems—such as smart security cameras, embedded voice assistants, and autonomous delivery drones—execute multiple concurrent AI inference pipelines on compact single-core System-on-Chips (SoCs) equipped with limited physical RAM (often 512MB to 2GB).

Each deep learning workload imposes strict deadlines: a collision-avoidance model missing its deadline may result in hardware destruction, whereas a speech recognizer can tolerate slight delays. Simultaneously, neural models require multiple memory pages (virtual memory working sets) to hold intermediate activations and layer weights.

The Core OS Challenge: Who runs next on the CPU? How many physical frames should each job receive? When memory is full, which resident page must be evicted to prevent CPU stalls?

CPU Scheduling

FCFS • SJF • RR • Priority • EDF

Schedulers determine execution sequence. FCFS incurs convoy effects; SJF minimizes average waiting time; Round Robin provides fair interactive response; Priority guards critical tasks; EDF guarantees deadline feasibility under bounded load.

When Each One Wins:

  • FCFS: Batch pipelines where context switches must be strictly minimized.
  • SJF: Scenarios prioritizing minimum average waiting latency when burst durations are known.
  • Round Robin: Multi-tenant edge services requiring rapid initial response times.
  • Priority (with Aging): Critical tasks like obstacle detection; aging prevents lower priority starvation.
  • EDF: Hard real-time inference workloads where total utilization ≤ 1.0.

Deadlines & Metrics

Response • Waiting • Turnaround • Misses

Real-time operating systems evaluate dispatch performance using deterministic discrete time metrics: response time, turnaround time, waiting latency, and absolute deadline violations.

Formal Metric Formulations:
• Response Time = t_first_run - t_arrival
• Turnaround Time = t_finish - t_arrival
• Waiting Time = Turnaround - Burst
• Deadline Miss = t_finish > t_deadline
• CPU Utilisation = (Busy Ticks + Fault Stall Ticks) / Elapsed Ticks

Frame Allocation

Equal • Proportional • Priority

Physical RAM must be partitioned across concurrent active inference tasks. Equal divides slots uniformly; Proportional allocates based on virtual footprint; Priority rewards latency-sensitive pipelines.

In edge SoCs, Equal allocation unfairly starves heavy feature extractors while giving surplus memory to tiny telemetry tasks. Proportional allocation sizes partitions according to virtual working sets, mitigating unnecessary page thrashing.

Virtual Memory & Fault Stall

Demand Paging • Stall Penalty

When an execution tick accesses a virtual page not resident in physical memory, the hardware triggers a Page Fault interrupt. The CPU incurs a multi-tick fault stall while the kernel fetches the page from swap or flash.

Crucially, in embedded operating systems, page-fault stalls count directly against CPU time and delay deadline completion. A job with high burst efficiency can still miss its deadline if it suffers recurring memory fault stalls.

Expand Concept Details ▾

Page Replacement

FIFO • LRU • Optimal (Belady's MIN)

When all allocated frames are occupied, the kernel selects a victim to evict. FIFO evicts earliest arrived; LRU evicts least recently accessed; Optimal evicts the page with furthest future reference (theoretical lower bound).

Optimal replacement requires future knowledge of reference strings, serving as the benchmark standard. LRU approximates optimal performance via temporal locality.

Expand Concept Details ▾

Pressure & Thrashing

Working Sets • Thrashing Point

Thrashing happens when the combined working sets of active processes do not fit in available memory, not simply when total virtual footprint exceeds physical frame count.

When combined working sets exceed physical RAM, processes spend more time swapping pages than executing instructions. CPU utilization plummets, latency escalates, and edge devices fail their real-time safety guarantees.

Expand Concept Details ▾
Belady's Anomaly for FIFO Replacement
Under FIFO, allocating more frames can paradoxically increase page faults! The reference sequence 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 yields 9 faults with 3 frames and increases to 10 faults with 4 frames. Verified in our engine.
EDF Feasibility Theorem & Overload Behavior
Earliest Deadline First (EDF) is mathematically optimal only when total utilization ≤ 1.0. Under transient edge overload (∑ C_i / T_i > 1.0) or unexpected page-fault stalls, EDF experiences domino deadline misses.
